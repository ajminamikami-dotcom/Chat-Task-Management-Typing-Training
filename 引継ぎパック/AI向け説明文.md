# AI に最初に貼る説明文（コピーして会話の 1 通目に貼る）

以下はアプリの前提です。この前提を守って回答してください。

## アプリ
- 名前: チャットタスク管理・タイピングトレーニング（就労移行支援事業所の訓練用）。
- 1 つの HTML ファイル（`チャットタスク管理_タイピングトレーニング.html`、約 2,700 行）だけで動く。外部ライブラリなし、サーバーなし、ビルドなし。
- Level 1 = 選択式（11 問、全件完了で終了）、Level 2 = タイピング（20 問、制限時間 5/10/15 分、新着が順に届く）、Level 3 = Level 2 + 電話の割り込み（6 種類の相手）。
- 利用者は「受信トレイでチャットを選ぶ → 優先度（高・中・低）を選ぶ → 返信する（選択肢 or お手本をタイピング）か『返信せずに完了』」を繰り返す。結果画面で完了数・優先度正答率・返信正答率・平均処理時間・助言・要確認タスクの表・CSV が出る。
- 設定（レベル・時間・ゆったり表示）は localStorage のキー `chatTypingTrainingSettings` に保存。

## ファイルの区画（本体の中の順番）
CSS → 開始画面 HTML → ゲーム/結果/着信/停止の HTML → `<script>`: 問題データ（LEVEL1_DATA / TYPING_DATA / PHONE_DATA）→ els → **Logic ブロック**（`/* @@LOGIC_BEGIN` 〜 `/* @@LOGIC_END */`）→ state → bindEvents → 操作の門番（gate）→ 設定 → startGame と新着・着信の予約 → 描画（renderAll ほか）→ finishChat / 着信 / 一時停止 → endGame / 結果画面 / CSV / 補助関数。

## 守るべき原則（変更提案の前提）
1. **判定・集計・助言文・CSV・入力一致の規則は Logic ブロックの中だけ**にある。Logic は純粋（state・DOM・Date.now・乱数を参照しない）。規則を変えるときは、先に仕様書 `dev-tests/spec/judgment-spec.md` を変え、次に Logic、次に参照実装 `dev-tests/ref/ref-a.js`・`ref-b.js`（仕様だけを見て書かれたもの）を更新し、`node diff-check.js` の不一致 0 と `node golden.js` で出力の変化を確認する。
2. **操作の門番**は 1 つの原則「画面が切り替わった直後は、切り替わる前の画面に向けた操作を受け付けない」（定数 400 ms / 700 ms・24 px / 500 ms）。ダブルクリックや連打で判定が確定しないための仕組みで、0.4 秒だけクリックが無視されるのは仕様。
3. **問題データの正解は手書きしない。** 本文の属性（至急・期限あり・「返信不要」表記・個人の声かけ・依頼あり）を `dev-tests/ref/answer-table.js` に根拠語つきで登録し、規則表から導く。本文に根拠語が無いと検査 `e2e07` が落ちる。
4. 「返信不要」と書かれた連絡に返信すると不正解になる表示は、わざと残している（トラップ）。
5. CSV の行は受信番号（id）順。一時停止中の時間は処理時間に含めない。
6. 本体を複数ファイルに分けない。縮小・圧縮もしない。

## 回答の仕方
- 変更案は「どの関数の、どの行の前後に、何を足す／消す」の形（アンカーつきの差分）で示し、ファイル全体の書き直しは出さない。
- 変更の前に、その挙動が仕様（上の原則）で意図されたものでないかを確認し、意図されたものなら変更しない。
- 変更後に実行すべき検査コマンド（例: `cd dev-tests` → `set QUICK=1` → `node run-all.js`）と、合格の目安を添える。
- 分からないことは推測せず、「どのファイルを貼れば答えられるか」を聞く。
